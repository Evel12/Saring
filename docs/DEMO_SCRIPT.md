# Four-minute Saring demonstration

Use only synthetic records. Start the API, worker and web. Configure local Tesseract in the worker environment for the scan exercise; keep a separate private browser window for candidate invitations. The persistent DEMO banner means model/email/calendar are simulated; generated DOCX/PDF parsing and local OCR are real tools. A faster 3–5 minute presentation may use the exploration samples; the automated UI journey separately verifies custom creation.

**0:00–0:35 — Problem and role-specific criteria.** Explain that a CV often leaves an important requirement unanswered; missing evidence is not inability. Show **Create vacancy** alongside **Explore complete demo**. Create a custom Customer Support role, choose **Suggest criteria · DEMO**, edit “handle complaints,” the observable expectation and accepted evidence, then explicitly approve and publish. Explain that live suggestions need configured server credentials and are never silently simulated.

**0:35–1:10 — Real source extraction.** Use **Add synthetic file / Customer Support readable DOCX**, then **Run agent**. Open Rina's Overview/Evidence: actual paragraph references, exact source passage, unknown complaint-handling gap and candidate-reported provenance. Use the feed to show real extraction duration. Do not call coverage an accuracy or match score. The five-person/two-vacancy exploration seed is available for instant comparison.

**1:10–2:05 — Bounded clarification.** In Clarification inspect the concise complaint question, exact contact scope, deadline and zero/one reminder policy. Approve the specified request. Open its DEMO mailbox link in the separate browser. Give this synthetic answer: “I handled a complaint about a damaged order. I checked the order and courier records, offered a refund or replacement, arranged a replacement and confirmed receipt two days later.” Save a draft if desired; confirm actual submission. Return to HR: the worker resumes, appends unknown→partial with a response citation and candidate-reported label, and prepares an interview follow-up. Uncertainties remain visible; no expertise or hiring decision is inferred.

**2:05–2:55 — Human review and scheduling recovery.** HR records shortlist with a reason, generates/edits/approves the source-linked brief, and approves the exact interview plan and recipient separately. The candidate first replies “Thursday afternoon”: show confirmation required and no guessed booking. Offer an explicit dated window. In HR choose **Simulate calendar conflict · DEMO**; candidate selects the first option. The worker rechecks and reports conflict, then candidate explicitly selects an alternative. Show simulated booking and stable event ID. No email was sent or read and no Google account was touched.

**2:55–3:25 — General purpose, not a coding screener.** Open **Software Developer · sample**: same five synthetic people, separate application records and different approved requirements. Show Go evidence and unknown artifact/code-sample evidence. The optional portfolio is private; no URL is fetched, Python projects do not contradict Go, and HR can approve an alternative walkthrough question. Show the hostile-instruction sample: it has no tool authority or automatic selection effect.

**3:25–4:10 — Tools, recovery and measured metrics.** Show the scanned synthetic PDF's actual Tesseract/page/quality record, and the unreadable-file route: exclude with a reason, retain the original, add readable replacement, reanalyze. For a live restart demonstration stop the worker while a candidate answer is pending, submit the answer, restart the worker and show its queued continuation finishing without repeated email. The opt-in automated restart test also kills a process during analysis and induces lease expiry, then verifies recovery. In Metrics distinguish processing from waits; unavailable model usage/cost and HR time remain unmeasured. Mention that credentialed Google/Resend/model tests and public deployment were not performed.

Finish on the dashboard, with candidate/organization isolation and a human decision still central. Use [TEST_REPORT.md](TEST_REPORT.md) for the exact checks and limits; never imply the scripted DEMO adapters are live integrations.
