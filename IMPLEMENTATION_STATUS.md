# Saring frontend and backend status

The frontend now uses the real v1 organization-scoped API and preserves the reference's compact three-column dashboard. It adds all seven requested screen groups, scoped candidate draft/profile/consent flows, versioned brief editing and persisted event reconnection. The backend retains its authenticated relational foundation. Docker is optional; CMD scripts use SQLite by default.

## External configuration and limits

- Docker is unavailable here; Compose/PostgreSQL runtime and concurrent-worker PostgreSQL load tests were not exercised. Database DDL/triggers support PostgreSQL, but that path still needs integration validation.
- LIVE requires `SESSION_SECRET`; secure cookies default on. Local HTTP may explicitly use `COOKIE_SECURE=false`. Hosted use requires HTTPS, explicit origin configuration, password recovery/onboarding policy and secret rotation.
- Tesseract is required for scanned PDFs and is now verified on a generated image-only synthetic scan. `setup-ocr.cmd` supplies an optional workspace-only runtime detected by `start-worker.cmd`; no binary is committed. The worker preserves raw private extractions, then conservatively filters professional lines for association. This can omit relevant evidence and does not guarantee complete sensitive-data removal or eliminate bias.
- The automatic foundation reviewer is deliberately conservative: explicit CV claims can produce partial findings only when their evidence type is accepted; unavailable evidence stays unknown. Concrete accepted requirement-linked answers may move unknown to partial; weak/declined answers do not resolve a gap, and no source is automatically promoted to expertise or authorship. Recruiters make substantive judgments and all selection/hiring decisions.
- Google Calendar needs organization-specific server OAuth credentials. Credentialed calendar/model calls were not exercised. OAuth consent/refresh and calendar rescheduling are implemented; real test-account execution still requires credentials. The Resend adapter is implemented for approved clarification; no real credentials or inbox-delivery webhooks were exercised. Provider acceptance is not confirmed delivery.
- Offline, tenant-scoped withdrawn-application erasure and restartable private-file cleanup are implemented. Backups, physical media, provider copies, exports and legal holds need separate operator procedures; archive is not erasure. Hosted use still needs backup policies, encryption, malware/process isolation, quotas and operational review.

The inline reference HTML was used for the original visual implementation because no reference attachment existed on disk. `reference/saring.html` remains a compact reconstruction of that supplied design.

## Bounded clarification (previous phase)

Implemented an executable persisted workflow, one automatic round per approved criteria version and at most three questions. Essential material gaps precede preferred ones; existing detailed evidence, permissible source types and already asked stable criteria constrain questions. The model proposes typed retrieval/draft/escalation/revision actions, validated against state/ownership/budgets. It stores only concise action rationales/results and provider/prompt versions. One approval freezes the exact questions, response deadline and zero/one reminder policy. Demo delivery is an isolated mailbox; live uses the fixed Resend adapter with idempotency keys, bounded retries and a conservative provider replay window. No live or demo worker fabricates candidate answers.

Submission writes immutable answers/evidence and its continuation in one transaction. Identical retries return the same receipt; changed retries must append a factual correction. Leased continuation recovery works across worker restarts and dead leases. Detailed accepted self-report can change unknown to partial; weak or declined answers remain unresolved, and source conflicts are not automatically erased. Artifacts are labeled artifact-backed for their presence, with authorship/contents unverified. Revisions include before/after statuses, new evidence IDs, response/correction sources and a concise reason. Completed briefs persist remaining uncertainties and interview follow-ups. Received answers whose update fails are never labeled a no-response timeout. Changed criteria/withdrawal revoke the prior authorization before reminders.
